# 独立执行 agent：v0 独立生产底座

日期：2026-09-19。此文件记录真正会输出游戏动作的第一版自有 agent；它与 V45 无代码/路线共享，不报名、不提交 Kaggle。

## 当前能做什么

`lab/portfolio_agent.py` 的 `portfolio_executor` 每回合直接读取 observation：

- 每天 hour 0 依据当前已见维护工作，有限地 HIRE；
- 先处理已有动物 FEED、成熟货 HARVEST、作物 WATER、杂草 DIG；
- 给工人保留目标，避免每一步来回改主意；
- 使用 70/30 模型中排名最高的作物，在空地和现有种子允许时 PLANT；
- 在 hour 0 卖出 shed 内的产品，但为已有动物留当天小麦；
- 对排名靠前、现金和目标数量均允许的动物，依次 BUILD 对应棚舍、市场 BUY、从 shed PICKUP、在棚舍 PLACE；
- 每天先把小麦从 shed 取到手上，再 FEED 已放置动物；只有实际已喂过的动物才执行 CARE。

这仍只是最小可执行版本：不买土地，没有复杂的市场择时或逐日最短路径优化，也没有根据对手改变经营组合。70/30 目前只用于选择新增生产方向，不能理解成每回合强制按比例行动。

## 安全设计

同一回合的 PLANT 目标会按现有种子数预约，避免触发官方“同作物请求超过种子时全部失败”的原子规则。所有已有维护任务优先级高于新种植。任务目标每回合都用新 observation 重验：完成、改变或失效后释放，不沿用过期动作。

## 功能验证，不是强度结论

本机 720 回合、seeds 0–3：

| 对手 | 自有 agent 平均现金 | 对手平均现金 | 平均差 | 结论 |
| --- | ---: | ---: | ---: | --- |
| 官方 starter | 36,791.25 | 3,503.75 | +33,287.5 | 4/4 `DONE/DONE`，每局均实际放置 2 头动物、每日喂养/照料 |
| 冻结 V45 | 21,299.5 | 166,139.75 | -144,840.25 | 4/4 `DONE/DONE`，每局均实际放置 2 头动物、每日喂养/照料，仍远弱于主基线 |

这四个 seed 只是功能门，不能映射 Kaggle 排名。实现中曾发现两个会造成假象的执行错误：喂养者没有先取小麦，以及第二头已买动物因数量上限留在 shed；均已通过逐回合 trace 修正，最终四局都记录到 2 次真实 PLACE 和连续 FEED/CARE。尤其 V45 的市场微结构、工人路线和动物/作物组合都更完整；v0 仍大幅落后，不能称策略有效。

## 下一步

动物包已完成并通过上述功能门。下一道已批准的验证门是固定开发集的七对手 paired league：每个对手、seed、座位下，分别运行本 agent 与冻结 V45，比较终局现金。

该门已运行完成：`7 opponents × seeds 0–3 × 双座位 = 56` 个配对条件，候选和 V45 各 56 局，共 112 局；账本无重复。候选相对 V45 的平均终局现金差为 **-80,740.411**，七个对手均为负：sdy2842 `-66,131.25`、v46 `-66,551.25`、indar_top10 `-73,278.75`、kaito_v58 `-88,768.375`、nathan_pipe7 `-77,321.125`、boatlee_v16 `-107,172.75`、indar_pasture `-85,959.375`。所以 v0 **未通过开发集晋级门**，不会运行 holdout，也不能报名或提交。原始账本是 `experiments/portfolio_executor_v0_league_v1.jsonl`。

下一轮不是调一个分数阈值，而是先诊断这些差距具体来自什么：土地扩张、生产投资选择、工人日内路线、仓库/市场卖货，还是终局兑现；每次只提出一个可验证的能力补全，再用同一配对联赛测量。
