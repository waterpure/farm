# 70/30 经营组合：v2.1 公式修复与影子验证

日期：2026-09-19。v2.1 不是新策略；它只修复 v2 对番茄/草莓重复产出的错误解释。

## 修了什么

番茄和草莓的规则是“每次基础生产 1 份，整株最多生产 4 次”。v2 错把 `4` 当成每次生产量，又在每个周期重复计算，虚构出几十份产出。v2.1 把两个概念拆开：

- `units_per_yield_event`：一次生产多少份；
- `max_yield_events`：整株最多发生多少次生产。

因此，开局时番茄和草莓的基础总预估都为 4，不再会因为赛季还很长而无限增加。一次性作物仍是一株一次收成；动物仍按“每天喂养、但不额外 CARE”的保守基础线，不把 CARE、建筑和走路等另一个问题混入本修复。

旧 v2 文件没有覆盖。v2.1 使用独立 protocol 和输出文件。

## 验证

固定开发池：7 个外部对手 × 4 个 seed × 双座位 = 56 局。

- 编译通过；
- 开局 unit check：番茄 = 4、草莓 = 4 份基础总产量；
- 56/56 `DONE/DONE`；
- 56/56 终局现金严格等于对应冻结 V45 对局；
- 记录 1,680 份每日建议（56 × 30 天）。

所以 v2.1 仍没有控制 V45、没有产生策略分数、没有提交任何内容。

## 修复前后，建议为什么变了

| 主生产线 | v2（错误公式） | v2.1（修复后） |
| --- | ---: | ---: |
| 番茄 | 684 | 24 |
| 草莓 | 488 | 0 |
| 西瓜 | 0 | 576 |
| 小麦 | 154 | 557 |
| 胡萝卜 | 242 | 409 |
| 羊毛 | 0 | 2 |
| 无可回本线 | 112 | 112 |

次生产线中，牛奶出现 278 次，羊毛 34 次，蛋 12 次。也就是说，修复后即使暂时不算 CARE，动物也不再被机械排除；但没有理由把这当作“养动物一定最优”。

相同的商店组合也不会强制同一答案。例如第 8 天已经开 Bakery + Pizza Shop 的公开局面中，主线分别出现西瓜 4 次、小麦 2 次；当时的市场价格/库存、可见对手生产和剩余时间不同。它不是十三条写死路线。

## 仍未解决的边界

v2.1 只是消除了明显的“产出次数 × 单次产量”错误。它仍没有把以下事情做成可执行的每日计划：

- 动物每天 CARE 的额外产出，与其多占一次行动之间是否值得；
- 建棚、取放动物、收货、送货、走路和雇工的实际时间；
- 同一天现金、格子、小麦饲料与仓库之间的冲突；
- 如何把 70/30 建议落实为合法的农夫/雇工动作。

这些不应偷偷塞进参数。若要继续，必须先审核一个“显式行动成本 + CARE 方式比较”的方案，然后先做新的只读影子验证，仍不直接接管 V45。
