# V45 可解释机制地图（冻结开发基线）

来源为本地 SHA 验证过的公开 `third_party/v45/main.py`。自 2026-09-17 起，它是本项目的冻结开发基线。本文件将其拆成可定位、可验证的机制，帮助派生 variant 时只改变一个模块；它不改变第三方来源、Apache notices 或后续提交前必须完成的出处审查要求。

| 机制 | V45 中的表现 | 可迁移的原则 | 我们的处理 |
|---|---|---|---|
| 路线压缩 | 多条预计算 action tape，按开局商店选路线 | 先缩小高层经营选择，避免全动作搜索 | 冻结原路线；未来 variant 只在有明确假设时改变选择条件 |
| 执行安全层 | weed repair、预算、容量、dead stock | 基础计划要能在现实 obs 偏离时修复 | 先测每个保护层的触发次数/终局影响，再决定是否改一项 |
| 市场顺序 | 按订单排序、卖货抢先、clone race | 共享市场里订单位置与对手公开动作都重要 | 首个候选改动方向之一；先建同 seed 的价格/成交归因 |
| 现金/物资预留 | 预留种子、小麦、饲料、雇工成本 | 不能为当期套利破坏未来关键动作 | 单独评估预留规则，避免与路线修改混合 |
| 动态经济层 | 肥料 ROI、可跳过的喂养、供给补足 | 投资需要剩余时间、路径、容量共同约束 | 作为后续独立 variant 候选 |
| 终局计划 | 最后 7 回合按物理送达能力重新规划并清仓 | 终局只承认能送到 shed 并卖出的货 | 先记录终局库存与未兑现货物，再决定改动 |
| 对手适应 | 基于公开位置相似度识别 clone/race | 不知道私有库存，也能根据公开田地/位置估计供给 | 先验证触发准确性，不能凭函数名假设有效 |

## 当前源码定位

- `Chassis` 和通用 reactive 层：约 223–910 行。
- 路线表/商店到路线映射：约 945–970 行。
- 后续大量 `agent` wrapper 是累积实验层；阅读时需逐层确认最终覆盖顺序，不能把函数名出现当作启用证据。
- clone/race 机制约 3384 行之后。

## 冻结原件不直接编辑的部分

- 任何 route tape、压缩数据和其精确开局市场攻击；
- 未单独验证的实验性 wrapper；
- 有待审查 replay/路线来源链的内容。

上述内容可以随 V45 原件作为基线运行，但若要改变，必须做成单独具名 variant 并保留精确 diff；不能覆盖 `third_party/v45/main.py`。

## 用作开发基线的原因

V45 的本地最终现金远高于 starter 和玩具策略，因此适合作为每个 variant 的同 seed 回归对照。但本地 raw cash 与公开榜单数值量纲不一致；只能把它当相对基线，不能把对局现金映射为正式奖牌概率。
