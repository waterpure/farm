# V45 空任务槽：每局单一候选排序 v1

## 做了什么

这一步没有重跑任何比赛，也没有改变 V45。它只读取即时照料旁观验证 v3 的 56 条有效记录，在每一局已发现的候选中至多提名一个。

统一规则：

1. 资格必须已满足 v3 的全部条件：空地、原本 PASS、已有种子、同一人 1–2 步内在同格 WATER、原路线还有成熟期 HARVEST 和同类 SELL 窗口；
2. 第一排序：`保守预计卖货收入 − 种子机会成本`；
3. 如金额相同：更早卖出的优先；再按固定的坐标顺序打破平局。

没有“西瓜加分”、没有对手名称、坐标或回合的特例。

## 结果

- 56 条有效输入中，52 条得到一个唯一提名；4 条没有任何合格候选。
- `sdy2842` 的 8/8 都选择第 18 步 `(0,4)` 的 MELON；预估净值 1,420，原路线第 19 步立即浇水、第 246 步收获、第 249 步卖货。
- 其余 44 条提名 WHEAT。它们的预估净值只有 40–90，远低于西瓜；之所以不是草莓，是在这套保守收益估算下草莓没有排到第一。

这说明同一条通用排序规则会在不同局面提出不同作物，并非“只要看到空地就种西瓜”。但它还没有证明小麦提名真的应该执行。

## 最重要的限制

这是一个**赛后旁观排序器**：它已看见 V45 原本未来会在哪里浇水、何时收、何时下卖单，才给现在的空位打分。

真实对局在第 18 步看不到第 246 步。因此该排序器不能直接接到比赛 agent 上。它目前只证明：如果路线后来确实照原样走，怎样的“既有空档”在账面上最值钱。

要做可执行策略，下一步必须把“未来会浇/收/卖”的赛后信息，替换为当下能知道的承诺：例如 V45 自己已选定路线中的任务表、现有库存/价格和当前现金。那是一个新的设计问题，不能把这份赛后结果当成收益或比赛成绩。
